# Iustitia support and issue guide

Use the right channel so maintainers can reproduce and prioritize the problem.

## Public issues

Open a public issue when the report does not contain sensitive information.

### Bug report

Use for:

- A crash.
- A command or screen that does not work.
- A broken build or development workflow.
- A feature regression.
- A replay, clip, persistence, or rendering failure.

Include:

- Iustitia version or commit.
- Minecraft version.
- Fabric Loader and Fabric API versions.
- Java version.
- Other relevant mods, especially Sodium, Iris, ViaFabricPlus, C2ME, Freecam, or rendering mods.
- Operating system and graphics card for rendering problems.
- Exact reproduction steps.
- Relevant `latest.log` lines and crash report excerpts.
- Whether the issue reproduces with a minimal mod set.

Redact usernames, server addresses, IPs, tokens, paths containing personal information, and private chat before posting logs.

### Detection report

Use for a false positive, missed detection, or questionable confidence/tier behavior.

Include:

- Check ID.
- Server protocol or whether ViaFabricPlus was involved.
- Approximate tick/time of the event.
- Player movement/combat context.
- Whether the server was lagging.
- Relevant verbose log lines.
- A replay/clip or sanitized trace if you can share one legally and safely.
- Why the behavior is expected to be legitimate or suspicious.

Do not identify a player publicly as a cheater based only on an Iustitia alert. Reports are inference evidence, not server enforcement decisions.

### Compatibility report

Use when behavior depends on:

- A Minecraft version.
- Fabric Loader/API version.
- ViaFabricPlus protocol translation.
- A specific server.
- A graphics stack or rendering mod.

State whether the problem occurs with only Iustitia and its required dependencies.

### Feature request

Explain the user problem first. Include the proposed behavior, constraints, privacy implications, and how it should be verified. A feature request is not automatically a request to add another mixin or detector.

## Discussions and questions

Use GitHub Discussions for design exploration, usage questions, research ideas, and proposals that are not yet actionable issues. If Discussions are not enabled, open an issue with the `question` or `design` label and clearly mark it as exploratory.

## Security and privacy

Do not open a public issue for:

- A way to send data unexpectedly.
- A path that exposes local files or credentials.
- A vulnerability in packet suppression or local-player control.
- A crash or exploit that could affect users before they can disable the mod.
- Unpublished exploit details that should not be public yet.

Use [SECURITY.md](SECURITY.md) instead.

## What maintainers may close

Issues may be closed when they are:

- Duplicates.
- Not reproducible and missing requested details.
- About unsupported Minecraft versions without a compatibility contribution.
- Requests for server-side enforcement, bans, or remote reporting, which are outside Iustitia's scope.
- Accusations about identifiable players.
- Missing privacy redactions.
- Generated by an agent without verification evidence.

A closed issue is not a judgment about the reporter. It usually means the report needs a different channel or more information.
